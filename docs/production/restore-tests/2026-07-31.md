### RPO/RTO interpretation

- Proven recovery-point evidence: the selected snapshot was 6 hours 32 minutes
  old when restoration started and was usable. Daily cadence still creates an
  approximately 24-hour worst-case backup-point interval; record-level data
  freshness was not inspected.
- Measured infrastructure restore time: 3 minutes 57.206 seconds from restored
  volume creation to database readiness.
- Measured restore-validation time: 8 minutes 4.656 seconds total.
- Not proven: a 15-minute RPO, PITR, earliest restorable point, complete
  application RTO, media/Redis recovery, or provider reconciliation.

### Isolation and controlled writes

The Fly Postgres cluster wrapper required production Consul secrets, which were
deliberately not copied. Fresh random database startup secrets were staged only
on the temporary app. PostgreSQL was started standalone from the restored data
directory with no Fly services or public IPs. Automatic crash recovery and a
checkpoint wrote only to the restored copy; validation SQL used explicit
read-only transactions. No production application was connected.

### Cost and retained resources

At published Fly rates, the started `shared-cpu-1x` 1 GB Machine costs about
$0.0082/hour and the 3 GB volume costs $0.45/month, prorated hourly. The exercise
used roughly eight minutes of running compute. The Machine is now stopped; its
root filesystem, the encrypted 3 GB volume, app metadata, and incremental
snapshots remain billable where applicable until deletion.

Do not run cleanup without separate approval. Required cleanup sequence:

1. `fly machine destroy 781232da052738 -a squadpitch-restore-validation-20260731`
2. `fly volumes destroy vol_458kej6xzpd0wmj4 -a squadpitch-restore-validation-20260731`
3. `fly apps destroy squadpitch-restore-validation-20260731`
